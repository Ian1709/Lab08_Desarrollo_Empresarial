EVIDENCIAS — API NAVEGABLE DE DJANGO REST FRAMEWORK (paso 7)
Servidor: py manage.py runserver 127.0.0.1:8000
Datos:    py manage.py seed_quiz --reset   (imprime los tokens y la contraseña de aula)
Navegador: pestaña sobre http://127.0.0.1:8000/api/

DESDE EL LAB EXTRA (Parte 3) LA API EXIGE IDENTIDAD:
- Sin identidad, la API responde 401 (no 403): primero hay que ser alguien.
- En el navegador se usa la autenticación por SESIÓN: entrar con el usuario
  «profe» (contraseña de aula «profe12345») en http://127.0.0.1:8000/api-auth/login/.
  Ese usuario es staff, así que la persona puede todo (crear, modificar y borrar).
- Los clientes de programación (quizctl.py, scripts/demo_api.py, agent/) usan
  TOKEN en la cabecera Authorization, no la sesión.

Los códigos de cada operación son los mismos que en el Laboratorio 8; solo cambia
el paso previo de identificarse.

==============================================================================
0) SIN IDENTIDAD — GET http://127.0.0.1:8000/api/examenes/
------------------------------------------------------------------------------
GET /api/examenes/
HTTP 401 Unauthorized
Content-Type: application/json

{"detail":"Authentication credentials were not provided."}

-> Código de estado: 401 Unauthorized

==============================================================================
0b) INICIO DE SESIÓN — GET y POST http://127.0.0.1:8000/api-auth/login/
------------------------------------------------------------------------------
GET  /api-auth/login/   -> 200 OK   (formulario con el campo CSRF)
POST /api-auth/login/   -> 200 OK   (tras iniciar sesión redirige a /api/)
Usuario: profe   Contraseña: profe12345   -> Código de estado: 200 OK

HTTP 200 OK

==============================================================================
